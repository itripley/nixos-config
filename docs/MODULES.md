## `flake.nix`

- **`unstableOverlay`** adds `pkgs.unstable` (nixos-unstable) for the few fast-moving tools, on
  both hosts. Everything else comes from stable.
- **`buildFixes`** (`overlays/build-fixes.nix`) is applied to both stable and `pkgs.unstable`.
  It patches packages that fail to build in the pinned nixpkgs (see below).
- **`localPackages`** (`overlays/packages.nix`) adds the packages in `pkgs/` as `pkgs.<name>`.
- **`nixpkgsModule`** sets those overlays and `nixpkgsConfig` on both hosts, so the Mac and the
  desktop get the same `pkgs.unstable`, build fixes and repo packages.
- **`nixpkgsConfig`**, used for both stable and `pkgs.unstable` so they can't drift apart:
  - `allowUnfree`: Steam, Resolve, VS Code, Plex, Obsidian, etc. are unfree.
  - `permittedInsecurePackages = [ "openssl-1.1.1w" ]`: needed only by Sublime Text 4 (see DESIGN §4).
- **Hosts are discovered** (DESIGN §12): every folder in `hosts/` is a machine. `isMac` checks
  for `darwin-configuration.nix`; the other folders are NixOS. `mkNixos` and `mkDarwin` build them
  all the same way, so a new machine is a new folder (`git add` it) and no edit here.
- **NixOS modules from inputs (`mkNixos`):** disko, `artcraft` (`programs.artcraft`), `vicinae`
  (the input-server wrapper) and `silent-sddm` (`programs.silentSDDM`, the login screen). They are
  inert unless a host's modules turn them on. NixOS-WSL's module is imported by `hosts/wsl` itself.
- **home-manager block:** `homeManagerModule` (shared with the Mac) sets `useGlobalPkgs` (same pkgs as
  the system), `useUserPackages` (user packages installed through the system profile),
  `backupFileExtension` and `extraSpecialArgs`. NixOS hosts add `sharedModules` loading
  plasma-manager, nix-flatpak's HM module and vicinae's HM module (which replaces home-manager's own
  `programs.vicinae`). Which home config a user gets is up to the host: `desktop.nix` gives olivia
  `home/olivia`, `hosts/wsl` gives her `home/linux`, a Mac host gives its user `home/darwin`.
- **Standalone home-manager (`mkHome`):** `homeConfigurations."<user>@<system>"` for every name in
  `standaloneUsers` (`olivia`, `olivi`) and every system in `standaloneHome`: `x86_64-linux` →
  `home/linux` (with the GUI apps), `aarch64-linux` → `home/shared`, `aarch64-darwin` →
  `home/darwin`. Each gets `home/standalone.nix`, the username and home, and on Linux
  `targets.genericLinux.enable` (XDG paths and the GPU drivers for Nix GUI apps). The package set is
  the same stable nixpkgs with the same overlays and config as the hosts (`nixpkgs-darwin` on the
  Mac), so the apps are the same derivations the desktop already has. A machine with another
  username needs it added to `standaloneUsers`.
- Outputs:
  - `nixosConfigurations`: `desktop-olivia`, `wsl`, and any PC `bootstrap.sh` added.
  - `darwinConfigurations`: `macbook-olivia` and any Mac `bootstrap.sh` added (nix-darwin,
    `nixpkgs-darwin`). See [MACOS.md](MACOS.md).
  - `homeConfigurations`: six standalone homes, above.
  - `packages.x86_64-linux`: `warp-cloudflare-gui`, `obsidian-plugins`, `vscode-marketplace`
    (`nix build .#<name>`), taken from the system's package set so overlays and unfree apply.
  - `formatter`, `checks` and `devShells` exist for **both x86_64-linux and aarch64-darwin**
    (`forEachSystem`, tooling from that system's stable nixpkgs). Each machine runs its own.
  - `formatter`: `nix fmt` runs nixfmt (via nixfmt-tree) on every `.nix` file except the generated
    `hardware-configuration.nix`.
  - `checks`: `nix flake check` runs `toplevel-eval` (instantiates every derivation in
    `evalTargets` for *this machine's* system: on Linux every NixOS host plus the x86_64 and
    aarch64 Linux standalone homes; on darwin every Mac host plus the darwin home; one home per
    system, since the users differ only by name; builds nothing) and `lint` (statix, deadnix,
    `nixfmt --check`). Takes about 26 s on the desktop (15 s before WSL and the homes were added)
    and about 40 s on the Mac.
    `toplevel-eval` uses `builtins.unsafeDiscardOutputDependency` on the `drvPath`: a plain
    `drvPath` string depends on every output in the build closure, so the check would fetch or
    build all of it.
  - `devShells.default`: `nix develop` gives nixfmt-tree, statix, deadnix, nvd and nil.

## `hosts/desktop-olivia/configuration.nix`

Which modules the desktop is made of, in order: its hardware config and disk, `common.nix`, then
`boot`, `amd`, `desktop`, `login-art`, `audio`, `networking`, `storage`, `gaming`, `services`, and
its own `machine.nix`. Plus `networking.hostName = "desktop-olivia"` (the Windows hostname) and
`system.stateVersion = "26.05"`, the release it was first installed with. **Never bump it**; it
isn't an upgrade switch. A PC that `bootstrap.sh` adds gets a file of the same shape.

## `hosts/desktop-olivia/machine.nix`

What only this PC has, moved out of the shared modules on 2026-11-10 so other machines don't get it
(DESIGN §12):

| Setting | Why |
|---|---|
| **`time.hardwareClockInLocalTime`** | Windows stores local time in the RTC (DESIGN §3). Was in `boot.nix`. |
| `fileSystems."/mnt/windows"` | Windows `C:` on the Fanxiang NVMe: `ntfs3` (kernel driver), **read-only**, automount, addressed by partition GUID, owned by olivia (`uid`/`gid`). Read-only so Linux can never corrupt the Windows install. Needs Fast Startup off. Used for one-time imports (SSH keys, wallpapers, Firefox profile). Was in `storage.nix`. |
| OpenRGB (`motherboard = "amd"`) | Same RGB control as Windows. Loads the AMD SMBus driver (Windows needed PawnIO for this). Was in `services.nix`. |
| `openrgb-colors` oneshot | Re-applies the Windows **lowpink** profile at boot: RAM and board black (off) in Direct mode, the Basilisk `#B29393`. The profile file can't be used through `startupProfile`: OpenRGB only applies a saved controller when its location matches, and the Windows locations are PawnIO SMBus and `\\?\HID#…` paths (Linux: `/dev/i2c-8`, `/dev/hidraw*`, and hidraw numbers can change between boots). Colors decoded from `lowpink.json` (OpenRGB stores `0x00BBGGRR`). The second Basilisk entry in the profile (`#644B5F`, "Unknown Variant") is a second HID interface of the same mouse that Linux doesn't list. `--nodetect` makes each call a client of the running server; without it, the CLI also probes the hardware itself and every device shows up twice. Waits up to 30 s for the server to list the Basilisk. Colors changed in the OpenRGB GUI last until the next boot. |

## `hosts/wsl/configuration.nix`

NixOS inside WSL for **any** Windows machine (DESIGN §12), set up by `scripts/bootstrap.ps1`. WSL
provides the kernel, disk and boot, so there's no hardware config, and one host serves every
Windows PC.

| Setting | Why |
|---|---|
| `inputs.nixos-wsl.nixosModules.default` | NixOS-WSL's integration (`/etc/wsl.conf`, boot, interop). Imported here, not in `flake.nix`, so the PCs don't load it. |
| `wsl.defaultUser = "olivia"` | The same user as on the PCs (`common.nix`, uid 1000, which NixOS-WSL also uses for its default user). NixOS-WSL's image starts as `nixos`; the change only takes effect after `nixos-rebuild boot` and two restarts, which `bootstrap.ps1` runs. |
| `wsl.useWindowsDriver` + `hardware.graphics.enable` | GPU acceleration through the Windows driver (Mesa's d3d12), for the GUI apps under WSLg. |
| `wsl.startMenuLaunchers` | The Linux GUI apps appear in the Windows Start menu. |
| `nixpkgs.hostPlatform = "x86_64-linux"` | Set by `hardware-configuration.nix` on the PCs; WSL has none. |
| `networking.hostName = "wsl"` | So `nixos-rebuild switch --flake ~/nix-config` (and nh) pick this host. |
| `home-manager.users.olivia` = `home/linux` | The CLI layer and the Linux apps, no Plasma. `services.easyeffects` is forced off: there's no PipeWire in WSL (WSLg's audio is a PulseAudio socket). |
| `system.stateVersion = "26.05"` | As on the desktop; never change it. |

## `modules/nixos/common.nix`

What every NixOS machine gets, PCs and WSL. Until 2026-11-10 this was the desktop's
`configuration.nix`.

| Setting | Why |
|---|---|
| user `olivia`, **`uid = 1000`** | Fixed, so files on the CIFS and NTFS mounts keep their owner. `storage.nix` and `machine.nix` read it from here. |
| groups `wheel networkmanager audio video docker gamemode i2c` | sudo; Wi-Fi/VPN changes; realtime audio; GPU; Docker without sudo; gamemode; DDC/CI monitor control. |
| `shell = pkgs.fish` + `programs.fish.enable` | WezTerm's Linux config launches `fish -l`; the fish VS Code extension was installed on Windows too. |
| `nix.settings.experimental-features` | Flakes and the `nix` command. |
| `auto-optimise-store` | Dedupe the store. |
| `extra-substituters` / `extra-trusted-public-keys` | `vicinae.cachix.org`, so the Vicinae flake input downloads instead of compiling (DESIGN §4). |
| `trusted-users` left at the default (`root`) | Not `@wheel`: a trusted user can set substituters or build hooks, which is root without sudo's password. Nothing here needs it (nh uses sudo). |
| **`nix.channel.enable = false`** | No legacy channels. `NIX_PATH` is only `nixpkgs=flake:nixpkgs` (the pinned input), so `<nixpkgs>` and `nix shell nixpkgs#…` match the system. |
| **`programs.nh`** with `flake = ~olivia/nix-config` and `clean` | `nh os switch` = friendlier `nixos-rebuild`; automatic GC keeps 10 generations / 14 days. Replaces `nix.gc`. The path is built from the user's home, and home-manager's live links read it back (`osConfig.programs.nh.flake`), so the checkout location is written once. |
| **`programs.nix-ld`** | Lets unpatched Linux binaries run: Mason-installed LSPs in LazyVim, the VS Code server, random downloaded tools. |
| `environment.systemPackages`: wget, curl, pciutils, usbutils | No `git`/`vim`: olivia gets `gitFull` and Neovim's vim/vi aliases from home-manager, root has nano, and Nix fetches flakes without a git binary. |

## `hosts/desktop-olivia/disko.nix`

See [DESIGN.md §2](DESIGN.md#2-disk-layout-hostsdesktop-oliviadiskonix). Key safety property:
`device` is the by-id path including the Samsung's serial, so it can't match the Windows NVMe.
**Always check `ls -l /dev/disk/by-id/ | grep Samsung` before running disko.**

## `modules/nixos/disk-layout.nix`

The same layout as the desktop's `disko.nix` (1 GiB ESP at `/boot`, btrfs labelled `nixos` with
`@`, `@home`, `@nix` and `@swap` subvolumes, zstd + noatime, a 16 GiB swapfile) for PCs that
`bootstrap.sh` adds. The disk is called `main` and has no device here: each host sets
`disko.devices.disk.main.device` to its own by-id path (with the serial, as on the desktop). The
installed system mounts by partition label (`/dev/disk/by-partlabel/disk-main-ESP`,
`disk-main-root`), so it doesn't depend on that path. The swap size is `mkDefault`, so a host can
override it. Two disks with disko's `main` labels in one machine would clash. The desktop keeps
its own file, because its disk is called `nixos` and changing it would change live mounts.

## `modules/nixos/nvidia.nix`

For hosts with an NVIDIA GPU (`bootstrap.sh` adds it when it finds PCI vendor `0x10de`).
Untested on real hardware; evaluated only.

| Setting | Why |
|---|---|
| `services.xserver.videoDrivers = [ "nvidia" ]` | Selects the proprietary driver; it applies on Wayland too, where X isn't running. |
| `hardware.graphics` + `enable32Bit` | As in `amd.nix`: Steam/Proton/Wine need 32-bit. |
| `hardware.nvidia.open = true` | NVIDIA's open kernel modules, which nixpkgs requires choosing explicitly: right for Turing (GTX 16xx / RTX 20xx) and newer. Older cards need `false`. |
| `modesetting.enable`, `package = …nvidiaPackages.stable` | KMS for Plasma on Wayland; the stable driver branch. |
| `boot.kernelPackages = mkForce pkgs.linuxPackages` | `boot.nix` uses `linuxPackages_latest`, which the driver often doesn't support yet; nixpkgs' default kernel is the one it does. |
| `nvtopPackages.nvidia` | GPU monitor. |

Ollama stays on the CPU here (`ollama-cuda` would build CUDA locally). Hybrid laptops (NVIDIA plus
an integrated GPU) also need `hardware.nvidia.prime` with the bus ids, set by hand; the script
warns about that.

## `modules/nixos/login-art.nix`

Fedora's login-screen art for SilentSDDM (`desktop.nix`): `backgrounds.rei2` and
`profileIcons.olivia`, pulled in with `requireFile` by hash, and the `General`, `LockScreen` and
`LoginScreen` settings that point at `rei2.png`. Split out of `desktop.nix` on 2026-11-10 because
the files are gitignored (DESIGN §9): a fresh checkout doesn't have them, and the build would fail.
Imported by the desktop. A new PC's `configuration.nix` has the line commented out; uncomment it
once `themes/art/sddm/` is copied in and both files are in the store (`nix store add-file`,
`home/olivia/themes/README.md`). `bootstrap.sh` does the `add-file` when the import is on, and stops
before touching a disk if the files are missing. `settings` is a plain `attrs` option that merges
top-level keys, and these keys don't overlap with `desktop.nix`'s, so the result is the same as
before the split.

## `overlays/build-fixes.nix`

Workarounds for upstream build failures found on the first real build
([VERIFICATION.md](VERIFICATION.md#first-real-build-2026-11-08)). Each one only touches its own
package, so nothing else gets rebuilt:

| Package | Failure | Fix |
|---|---|---|
| `vscode` 1.144 (and `vscode.fhs`) | nixpkgs' `postPatch` deletes `node_modules/@vscode/ripgrep/bin/rg`, which VS Code 1.144 no longer ships | link nixpkgs' ripgrep at the new `@vscode/ripgrep-universal` locations instead. Has an `assert` that fails if nixpkgs changes that snippet. |
| `openssl_1_1` (only for `sublime4`) | `test_afalg` fails on Linux 7.x (it exercises the running kernel's AF_ALG socket) | delete only that test |

(The `codex` fix went with codex on 2026-11-09.) After `nh os switch --update`, try removing each fix; if the
build still passes, the fix is no longer needed.

## `hosts/desktop-olivia/hardware-configuration.nix`

Generated during install by `nixos-generate-config --no-filesystems` (the repo originally held a
placeholder so the config could be evaluated from Windows). `--no-filesystems` matters because
disko already declares the filesystems; a second set would conflict. Re-run it (and copy the result
here) only if the hardware changes.

## `hosts/macbook-olivia/darwin-configuration.nix`

The Mac's nix-darwin host (DESIGN §11, [MACOS.md](MACOS.md)). Named `configuration.nix` until
2026-11-10; the `darwin-` name is what tells `flake.nix` it's a Mac (DESIGN §12). What any Mac gets
is in `modules/darwin/common.nix`; this file has what's specific to this one:

- `nixpkgs.hostPlatform = "aarch64-darwin"` (Apple M1).
- `networking.hostName` and `computerName` are `macbook-olivia`, so `LocalHostName` follows.
  `darwin-rebuild switch --flake ~/nix-config` picks this config from the hostname.
- `system.primaryUser = "olivi"`: the user that nix-darwin's user-level options (homebrew,
  `system.defaults`) apply to. Activation itself runs as root (`sudo darwin-rebuild`).
- `users.users.olivi.home` and `home-manager.users.olivi = import ../../home/darwin`: the account
  and its home-manager config (home-manager reads the username and home from `users.users`).
- `environment.etc."pam.d/sudo_local".knownSha256Hashes`: the hash of the hand-written file the
  Touch ID setting replaced, so the switch moved it to `sudo_local.before-nix-darwin` instead of
  aborting with "Unexpected files in /etc". A file with any other content still aborts.
- `system.stateVersion = 7`: never change it.

A Mac that `bootstrap.sh` adds gets a file of the same shape (without the hash: a fresh Mac has no
hand-written `sudo_local`), with `stateVersion` set to nix-darwin's newest.

## `modules/darwin/common.nix`

What every Mac gets. Until 2026-11-10 this was in the MacBook's host file.

- Imports `homebrew.nix` and `defaults.nix`, so every Mac gets the same apps and macOS settings.
- `security.pam.services.sudo_local`: `touchIdAuth` (`pam_tid.so`) and `reattach`
  (`pam_reattach`, so Touch ID also works inside tmux). Both lines can only let sudo succeed early;
  the password check in macOS's `/etc/pam.d/sudo` is untouched. macOS 14+ includes `sudo_local`
  on its own, so nix-darwin doesn't edit `/etc/pam.d/sudo`.
- `fonts.packages = [ nerd-fonts.jetbrains-mono ]`: into `/Library/Fonts/Nix Fonts`. It's
  WezTerm's icon fallback, as on the desktop (`desktop.nix`). TX-02 and the other personal fonts
  stay in `~/Library/Fonts` by hand.
- `nix.settings.experimental-features` and `nix.channel.enable = false`, as on the desktop.
  `trusted-users` stays root-only.
- `nix.gc` (`automatic`, `--delete-older-than 14d`) and `nix.optimise.automatic`: two root
  LaunchDaemons, `org.nixos.nix-gc` (Sundays 03:15) and `org.nixos.nix-optimise` (`nix-store
  --optimise`, Sundays 04:15), nix-darwin's default times. The desktop's equivalent is
  `programs.nh.clean` + `auto-optimise-store`; why the Mac differs is in DESIGN §11. If the Mac is
  asleep at that time, launchd runs the job when it wakes; if it's off, that week is skipped.
- `system.configurationRevision` comes from the flake's `rev`/`dirtyRev`, so `darwin-version
  --configuration-revision` shows which commit a generation was built from. (It also means the
  Mac's `drvPath` changes with every commit; compare with `nix-diff`, not by path.)
- Also here: `programs.fish.enable` (fish at a stable path for WezTerm) and macOS's own zsh prompt
  (`programs.zsh.promptInit`).

## `modules/darwin/defaults.nix`

macOS settings through `system.defaults`, captured 2026-11-10. Only values that differed from the
macOS defaults are declared, so the first switch changed nothing except rewriting the Dock list.
Anything here that's changed in System Settings, including Dock pins, is reverted on the next
switch; lasting changes go in this file. A rollback doesn't unset defaults: restore with `defaults
import` from the backup folder (MACOS.md).

| Setting | Value |
|---|---|
| `dock` | right side, tile size 34, no autohide or magnification, minimize into the app icon. `persistent-apps`: the 19 pinned apps, with WezTerm from `~/Applications/Home Manager Apps`. |
| `finder` | list view (`Nlsv`), path bar, new windows open Recents, no drives or servers on the desktop |
| `NSGlobalDomain` | automatic light/dark, natural scrolling off, trackpad speed 0.875 |
| `trackpad` | tap to click, secondary click in the bottom-right corner, pinch zoom and three-finger drag off. nix-darwin writes both the built-in and Bluetooth trackpad domains. |
| `menuExtraClock` | AM/PM and weekday |
| `WindowManager` | Stage Manager off, no tiled-window margins |
| `CustomUserPreferences` | Values with no typed option. `AppleKeyboardUIMode = 1`: the typed option only allows 0, 2 and 3. Also: no minimize on title-bar double-click, large menu bar font, don't reopen windows at login (`TALLogoutSavesState`), cursor in screenshots. |

Not managed: the `-currentHost` global trackpad keys (nix-darwin has no per-host domain; they're
already set), key repeat (at the default), wallpaper, login items, notifications.

## `modules/darwin/homebrew.nix`

Homebrew, declared through nix-darwin's `homebrew` module (DESIGN §11). Homebrew itself is installed
by hand, outside Nix.

| Setting | Why |
|---|---|
| `onActivation.cleanup = "none"` | Nothing undeclared is removed: the 8 stale casks, the brew copies of tools that now come from Nix, other taps. `"check"` would fail the switch while those exist; `"uninstall"`/`"zap"` only with Olivia's OK. |
| `onActivation.autoUpdate = false`, `upgrade = false` | A switch only installs what's missing (`brew bundle --no-upgrade`, `HOMEBREW_NO_AUTO_UPDATE`), so it's repeatable and never surprises with upgrades. Upgrading is a manual `brew upgrade`. |
| `global.brewfile = true` + `mas` in `systemPackages` | A plain `brew bundle check --no-upgrade` uses the generated Brewfile, and can check the App Store entries. Activation brings its own `mas`. |
| `taps` (pear-devs/pear, viceverse-cz/serein, anomalyco/tap), `trusted = true` | Only the taps a declared cask or brew comes from. Homebrew 6+ refuses untrusted third-party taps, which would abort activation. serein's tap lives at a non-standard URL (`clone_target`). |
| `brews` | Kept in Homebrew, "review later": build tooling for brew/Xcode builds that expect `/opt/homebrew` paths (cmake, automake, llvm@20, vcpkg, …), php/httpd, Python 3.11/3.13, rbenv, mpv, tailscale, chezmoi, projectm, mole. Also `cliclick` (not in nixpkgs) and `opencode` (nixpkgs' is older). `node` and `cloudflared` are in Nix too, but stay here because the openclaw LaunchAgent and the Cloudflare tunnel LaunchDaemon run Homebrew's paths. |
| `casks` | The 28 GUI apps still installed. GUI apps stay casks for Spotlight, code signing and their own updaters. |
| `masApps` | Keynote. Taphouse can't be declared, since the store no longer lists it (MACOS.md step 7). Needs an App Store sign-in. |

To add an app: a cask name from `brew search --cask`, then a switch. A removed line leaves the app
installed (`cleanup = "none"`); uninstall it with `brew uninstall` by hand.

## `home/shared/`

Home-manager modules **every machine** imports: through `home/linux` (the desktop, WSL, x86_64
distros), `home/darwin` (Macs), or on their own (ARM Linux standalone). Only things that work the
same on Linux and macOS go here. Platform-specific config stays in the platform's own home
directory (DESIGN §11, §12).

- `default.nix`: imports the others. It also has the **`xdg.configFile` live links** for `wezterm`,
  `nvim` and `fastfetch`, pointing into `~/nix-config/home/olivia/dotfiles/` (DESIGN §6). The path
  is built from `home.homeDirectory`, because nix-darwin has no `programs.nh`. The dotfiles stay
  under `home/olivia/` on both machines.
- `cli.nix`: Python + uv, docker-compose, tmux, mc, fastfetch, jq, gh, btop, and from Fedora: Go,
  rustup (cargo/rustc), lazydocker. All of them are in the binary cache for both systems.
- `shell.nix`: fish, with `fish_greeting = "krabby random 1-4 --no-mega --no-gmax --no-regional"` (a
  random Pokémon from generations 1–4, no mega, gigantamax or regional forms; krabby's default

## `scripts/bootstrap.sh`

Sets up a machine from this repo (DESIGN §12); how to run it is in
[OPERATIONS.md](OPERATIONS.md#setting-up-a-new-machine). It looks at where it runs, gets the
checkout to `~/nix-config` (clones it, or uses the one that's there), and then:

| Where | What it does |
|---|---|
| **NixOS USB installer** (`/etc/NIXOS` and `/iso` or a tmpfs root) | Needs x86_64 and UEFI. Asks for a name. A name already in `hosts/` is **reinstalled** with its own disk settings. A new one: lists the disks with size, bus, model and filesystems (the USB it booted from is marked and refused), writes `hosts/<name>/` with `nixos-generate-config --no-filesystems`, `disk-layout.nix` on the chosen disk's by-id path, and `amd.nix` or `nvidia.nix` from the PCI vendor ids, then `git add`s it. Then it evaluates the whole system, adds the login art to the store if the host imports it (and stops if the files are missing), shows each disk disko will wipe, and wants its kernel name typed. Then disko (`--inputs-from .`, so the locked version; it asks too), Unraid credentials into `/mnt/etc/nixos/smb-secrets` (optional), `nixos-install --no-channel-copy` (asks for root's password), olivia's password, and a copy of the checkout to `/mnt/home/olivia/nix-config`. |
| **NixOS, installed** | Hostname in `hosts/`: `nixos-rebuild switch` to it. Otherwise it **adopts** the install: a new `hosts/<name>/` with `nixos-generate-config` *with* filesystems (the disks stay as they are), the ESP path from `bootctl` (`efiSysMountPoint` when it isn't `/boot`), then `nixos-rebuild boot` after a confirmation. Refuses BIOS boots. olivia is created at the next boot, without a password. |
| **NixOS-WSL** | As olivia: `nixos-rebuild switch --flake .#wsl`. First run (as `nixos`): `nixos-rebuild boot`, because NixOS-WSL says a new default user must not be applied with `switch`; then it copies the checkout to `/home/olivia` (same uid 1000). `bootstrap.ps1` does the restarts. |
| **macOS** | Apple Silicon only. Command Line Tools, Nix (official installer) if missing, then: `LocalHostName` in `hosts/` → `darwin-rebuild switch` (the first time from `nix build`'s `result`, as in the README). Otherwise a choice: a new nix-darwin host (installs Homebrew if asked, writes `hosts/<name>/darwin-configuration.nix` for the current user with nix-darwin's newest `stateVersion`, switches) or home-manager only. |
| **Other Linux** (any distro, WSL distros) | x86_64 or aarch64. Nix if missing, then standalone home-manager: `nix run --inputs-from . home-manager -- switch --flake .#<user>@<system> -b hm-backup`. Stops if the user isn't in `standaloneUsers`. Offers to run `non-nixos-gpu-setup` with sudo, and prints how to make fish the login shell. |

Details:
- Every prompt reads `/dev/tty`, and the commands that prompt get `</dev/tty`, so it also works
  as `curl … | bash`. The Nix installer is downloaded to a temp file first, so its `sh` doesn't
  read the terminal as its script.
- Every `nix` call gets `nix-command flakes` (flags for the `sudo` calls, `NIX_CONFIG` for the
  tools nix starts), whatever the machine's `nix.conf` says. git comes from `nix run nixpkgs#git`
  when it isn't installed (the ISO).
- The files it writes are nixfmt-clean, so CI's lint passes once they're committed. A long by-id
  path goes on its own line, as nixfmt puts it.
- It never commits or pushes: the new `hosts/<name>/` is staged, and it says to commit and push
  it from the new machine.
- `BOOTSTRAP_SOURCED=1 source scripts/bootstrap.sh` loads the functions without running anything
  (how it was tested; [VERIFICATION.md](VERIFICATION.md#any-machine-deploy-2026-11-10)).

## `scripts/bootstrap.ps1`

The Windows entry point (`irm …/bootstrap.ps1 | iex`, or `pwsh -File scripts\bootstrap.ps1`). Runs
as the normal user:
1. If `wsl --status` fails, it runs `wsl --install --no-distribution` elevated, then asks for a
   reboot and a second run.
2. If there's no `NixOS` distro, it downloads `nixos.wsl` from NixOS-WSL's latest release and
   runs `wsl --install --from-file … --name NixOS --no-launch` (WSL 2.4.4+; it says to run
   `wsl --update` otherwise).
3. Runs `bootstrap.sh` inside the distro: the copy next to it, or the published one.
4. If the default user isn't olivia yet, runs NixOS-WSL's restart sequence (`wsl -t`, a root
   login, `wsl -t`), then reports the user.

`WSL_UTF8=1` makes `wsl.exe` print UTF-8 instead of UTF-16. Everything is inside a function, so
`return` ends it without closing the window when it's run through `iex`.
